# 《遗迹快跑》技术方案 v1（M0）

> 作者：程序　日期：2026-10-11　状态：初稿，待制作人确认后回填 GDD §14.1
> 结论先行：**Phaser 3.90.0 + TypeScript + Vite，序列帧图集动画，JSON 配置表，本地存档 + TapTap 云存档，纯前端无自建服务器。** 所有平台能力走平台抽象层，先接 TapTap H5。

## 1. 选型结论

| 项 | 决定 | 理由 |
|---|---|---|
| 引擎 | **Phaser 3.90.0**（锁版本，不跟 4.x） | 纯 Web 引擎，H5 包天然兼容；WebGL 自动合批、图集、BitmapText、对象池（Group）开箱即用；3.90 是 3.x 最终稳定版，资料和插件最多。Phaser 4 在 2026-04 才发正式版，生态还在迁移，首版不冒险 |
| 语言 | TypeScript 5.6（strict） | 配置表、存档结构都有类型校验，多人改不容易出错 |
| 构建 | Vite 5，产物 `dist/`（入口 `index.html`，TapTap H5 上传要求有 index.html） | 热更新快，产物是纯静态文件 |
| 渲染 | WebGL 优先，不支持时自动退回 Canvas | 目标 Draw Call ≤ 50（GDD §14.3） |
| 动画 | **序列帧 + TexturePacker 图集**；位移/缩放/闪白/抖动用程序补间和着色器 | 美术推荐的 B 风格（粗描边平涂）最适合序列帧；不引入 Spine，省运行时和授权费，包体也小 |
| 碰撞 | 自写圆形碰撞 + 空间网格，不用物理引擎 | GDD §14.3，120 怪 + 200 弹的性能目标 |
| 配置表 | Excel（按 GDD §17.1 三行表头）→ 导表脚本 → `public/config/*.json` → 启动时 `ConfigLoader` 加载并按类型校验 | 策划只改表不改代码；灰盒阶段先直接手写 JSON，导表脚本 M1 补齐 |
| 远程配置 | 预留：`config_version` + 远程 URL 覆盖 `global_param`（广告开关、频次等），首版可关 | GDD §14.2 广告远程开关 |
| 存档 | 本地 localStorage（同步、每次写）+ TapTap 云存档（节流上传） | 见第 3 节 |
| 后端 | **首版不自建服务器** | 登录 code 换 openid 需要服务端，首版不做账号体系，uid 本地生成；排行榜、分享走平台能力。邀请奖励归因、"击败 XX%"等需要服务器的功能按评审第 11 条后置 |
| 音频 | Phaser WebAudio，mp3；首次触摸后解锁 | 浏览器限制（GDD §14.2） |

## 2. 工程结构

```
/workspace/game
├── index.html            游戏入口
├── sdk-test.html         TapTap SDK 真机验证页（M0-3）
├── public/config/        配置表 JSON（global_param.json、skill.json、monster.json …）
├── public/assets/        图集、音频（按资源规范目录）
└── src/
    ├── platform/         平台抽象层：IPlatform + TapTapPlatform + WebPlatform（以后加 Wechat/Douyin）
    ├── config/           配置加载与类型
    ├── save/             存档管理（S1–S4、启动检查、迁移、云同步）
    ├── game/             场景、战斗、刷怪、背包、撤离、技能
    └── sdktest/          SDK 验证页逻辑
```

## 3. 存档方案（落实 GDD §14.5 / §17.2）

- **本地**：整份存档 JSON 存 `localStorage['rd_save']`，每次写入 `save_seq + 1`、`updated_at = now`，附简单校验和（防手改，非强反作弊）。写失败（存储满、隐私模式）时，S1 直接弹"存档失败，请重试"，不进局。
- **云端**：TapTap `tap.getCloudSaveManager()`（文档写明支持 H5 游戏；需先写入 `tapfile://` 本地文件再上传；单存档 ≤ 10MB；**每分钟最多上传 1 次**）。所以：
  - S1（出发）、S3（结算）标记为"重要"，立即尝试上传；若离上次上传不足 60 秒，排队到 60 秒后补传。
  - S2（每层快照）、S4（局外操作）只写本地，合并到下一次上传。
  - 切后台 `onHide` 时如果有未上传的数据，尝试补传一次。
- **冲突**：启动时拉云端，`save_seq` 大的为准；云端有未结算 `active_run` 时同样按阵亡结算（防清缓存逃结算）。
- **迁移**：`schema_version` 每升一版写一个 `migrate_vN_to_vN+1()`，启动时逐级执行。
- **异常退出**：启动发现 `active_run` 不为空 → 按 §4.3 配置阵亡结算 → `run_id` 写入 `settled_run_ids`（保留 20 个）→ 弹窗提示。

## 4. 平台抽象层

接口 `IPlatform`（`src/platform/IPlatform.ts`）：登录、激励视频/插屏、分享面板、好友面板、启动参数、排行榜提交/打开、云存档读写、本地 KV、系统信息与安全区、前后台、震动。所有方法失败不抛异常，统一返回 `{ok:false, err}` 或 `{result:'fail'}`，方便广告管理器兜底和打 `ad_result` 埋点。

运行时按全局对象自动选择实现：有 `tap` → TapTap；以后有 `wx` / `tt` → 微信 / 抖音；都没有 → Web 模拟（激励视频弹确认框模拟"看完/中途关闭"），这样普通手机浏览器也能试玩。

TapTap 侧用到的 API（均在官方文档查到；**是否全部在 H5 包内可用，未核实**，以真机验证为准）：
`tap.login`、`tap.createRewardedVideoAd`（单例，`onClose` 的 `isEnded` 为 true 才发奖）、`tap.createInterstitialAd`（每次新实例，用完 destroy）、`tap.showShareboard({templateId, sceneParam})`、`tap.onShareMessage`、`tap.openFriendList`、`tap.getLeaderboardManager()`（1.8.0+，`submitScores` / `openLeaderboard`；好友相关接口需在隐私协议勾选"好友关系"）、`tap.getCloudSaveManager()` + `tap.getFileSystemManager()`、`tap.getSystemInfoSync().safeArea`（部分机型不返回，需兜底）。

## 5. 性能策略（GDD §14.3）

- 对象池：怪、子弹、掉落物、伤害数字全部 `Group` 复用。
- 同屏上限读 `global_param.max_enemies`（120）/ `max_enemies_low`（80），超量的经验星星合并。
- 空间网格（格子边长 2 格）做碰撞和索敌，不上物理引擎。
- 一个区域的角色/怪/掉落/特效尽量打在 1–2 张 2048 图集里，伤害数字用 BitmapText，Draw Call ≤ 50。
- 帧率监测：连续 3 秒平均 < 45 帧自动降档（怪物上限 80、关部分粒子、降低分辨率倍率）；每 30 秒打 `perf_sample` 埋点。
- 分辨率倍率：渲染分辨率 = min(设备像素比, 2)，低端档降到 1。
- 包体：首包只放加载页 + 公共 UI + 花园资源，其他区域按需加载。首包目标 ≤ 4MB（GDD 目标；TapTap H5 包体上限**未查到**）。
- 前后台：`onHide` 立即暂停游戏和音乐，`onShow` 恢复；看广告期间同样暂停。

## 6. 以后上微信 / 抖音

Phaser 不能直接跑在微信/抖音的原生小游戏环境（没有 DOM），需要接适配层（社区方案是 weapp-adapter 一类，提供 document/window 模拟）。代价估计：适配层 + 两个平台实现类 + 真机调试，每个平台约 1–2 周；游戏逻辑不用改，因为所有平台调用都在抽象层里。**如果老板确定首版就要同时上微信/抖音，建议在 M0 内重新评估是否换 Cocos Creator**，换引擎的代价是灰盒原型重写（约 1 周）。

## 7. 风险与待确认

1. TapTap H5 包内 `tap.*` 能力是否齐全 —— 需要真机跑 `sdk-test.html`（见 `SDK验证说明.md`），**我这边没有手机，需要制作人安排**。
2. H5 包体上限、分包支持 —— 文档未查到，需提工单。
3. 登录换 openid 需要服务端；首版不做的话，云存档就依赖 TapTap 自己的账号绑定（云存档按 TapTap 用户隔离），这点要真机确认。
4. 1 格的像素数会影响所有手感数值（射程、移速、Boss 范围），我建议 64px（见资源规范），需要策划确认手感，灰盒里会做成可调。
5. 首版是否要同时上微信/抖音（影响第 6 节的引擎判断）—— 等老板拍板。
